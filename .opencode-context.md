**Quote Token Auth Flow (NEW — July 2026):**
1. Guest submits quote request (unauthenticated ✓) → Supabase auto-generates `quote_token` UUID via `gen_random_uuid()`
2. `QuoteForm` stores `quote_id` + `quote_token` in `localStorage`
3. Admin sends quote PDF → email includes `/quote/[id]?token={quoteToken}` link
4. Unauthenticated user lands on quote page → sees `QuoteClaimPrompt` upsell (feature list + sign-in/sign-up buttons)
5. User signs in → redirected back with token in URL → `customer-action/route.ts` calls `getUser()` (crypto-validates) + token matches → claims quote (sets `user_id`)
6. Authenticated user → sees `QuoteActionButtons` (Accept/Decline) + `CustomerBookingForm`
7. Booking implies acceptance — `book/route.ts` auto-sets status to `accepted` if still `sent`
8. All sensitive API routes require authenticated session (401 for unauthenticated)
9. `quote_token` passed in API body for claiming, not for bypassing auth

**Reviews System:**

## Database Schema — CRITICAL NOTES

### ⚠️ schema.sql synced with live DB (July 2026)

The `schema.sql` has been updated to reflect the live Supabase database after the July 2026 multi-tenancy and security sprints. `workshop_id` columns added to all tenant-isolated tables. `business_settings` PK converted to `workshop_id UUID` with 14 business fields migrated from `profiles`. `email_templates` and `email_logs` tables created. `quotes` table has `deposit_percent`, `deposit_amount`, `expiry_date` columns. `public.users` table confirmed removed.

### `is_admin()` function EXISTS

`schema.sql:1154` — `CREATE OR REPLACE FUNCTION public.is_admin()` with `SECURITY DEFINER`. Used by RLS policies for admin-only mutations.

### Reviews Table (VERIFIED)

```sql
reviews (
  id               UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  user_id          UUID REFERENCES profiles(id) ON DELETE SET NULL NOT NULL,
  quote_id         UUID REFERENCES quotes(id) ON DELETE SET NULL,
  customer_name    TEXT NOT NULL,
  customer_email   TEXT,           -- exists in live DB, NOT in schema.sql
  rating           INT NOT NULL CHECK (rating >= 1 AND rating <= 5),
  comment          TEXT NOT NULL,   -- named 'comment' NOT 'review_text'
  status           TEXT NOT NULL DEFAULT 'pending',
  moderation_notes TEXT,
  approved_at      TIMESTAMPTZ,
  deleted_at       TIMESTAMPTZ,
  created_at       TIMESTAMPTZ DEFAULT NOW(),
  updated_at       TIMESTAMPTZ DEFAULT NOW()
)
```

**Rules for review code:**
- Read: `review.comment` (NOT `review.review_text`)
- Read: `review.customer_email` (may be null)
- Write: `comment` field in insert
- Omit: `vehicle_serviced` entirely (column does NOT exist)
- Required: `user_id` must be included in inserts (NOT NULL constraint enforced)

## Error Handling (CRITICAL)

```typescript
// ❌ NEVER do this:
setError(error.message);

// ✅ ALWAYS use sanitizers:
import { sanitizeAuthError, sanitizeFormError } from '@/lib/auth-utils';
setError(sanitizeAuthError(error));   // auth forms
setError(sanitizeFormError(error));   // database forms
```

### ReviewForm Error Mapping
```typescript
function getErrorMessage(code, message) {
  if (code === 'PGRST204') return 'A database column is missing.'
  if (code === '23505') return 'This review already exists.'
  if (code === '42501') return 'No permission to submit.'
  if (code === '23502') return 'You must be signed in to submit.' // user_id NOT NULL
  if (message?.includes('does not exist')) return 'Database schema mismatch.'
  return message || 'Something went wrong.'
}
```
