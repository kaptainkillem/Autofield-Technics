# OpenCode Context Guide — Autofield Technics Mechanic Website

## Overview
This document provides context for OpenCode CLI to help generate consistent code for the mechanic service website.

---

## Project Status

**Current Phase:** Production-ready (June 2026)

**Completed Features:**
- Full services engine with 3 levels: `/services` → `/services/[category]` → `/services/[category]/[serviceId]`
- MobileStickyCTA (floating conversion bar on mobile + desktop)
- EmptyState (reusable fallback UI for errors and empty data)
- ServicesHero (hero with dynamic CTA support)
- Breadcrumb (navigation breadcrumbs)
- DynamicIcon (lucide-react icon lookup with tree-shaking)
- Terms & Privacy Policy pages
- Auth system (signin/signup/forgot-password/reset-password/onboarding)
- Logout functionality in header and dashboard sidebar
- Error sanitization (sanitizeAuthError, sanitizeFormError)
- RLS policies in schema.sql (note: `is_admin()` function does NOT exist — role check is done via `user.user_metadata.role`)
- Design token system (Tailwind v4 + CSS variables)
- Full admin dashboard with sidebar navigation

**Homepage Widgets (app/page.tsx):**
- `Hero` — centered text on mobile, CTAs stacked vertically, 2-col grid on desktop
- `ScrollingReviews` — fetches approved reviews from Supabase, horizontal scroll with snap on mobile
- `FeatureShowcase` — 3 alternating image/text feature sections
- `HowItWorks` — 3-step process grid, horizontal scroll on mobile
- `ServicesGrid` — fetches categories from Supabase, horizontal scroll on mobile
- `BottomCTA` — dark section, flush against footer

**Reviews System:**
- Public reviews page (`/reviews`) — displays approved reviews, includes ReviewForm
- Admin reviews approval page (`/dashboard/admin/reviews`) — approve/reject/delete pending reviews
- Reviews require authentication — ReviewForm shows "sign in" link and disables submit for anonymous users
- `user_id` must be sent with review submissions (authenticated users only)
- Reviews table uses `comment` column (NOT `review_text`) and `customer_email` column
- `vehicle_serviced` column does NOT exist in the database

**Client Dashboard:**
- Overview page (`/dashboard`) — quotes list, reviews section, quick actions
- My Quotes (`/dashboard/quotes`) — client's submitted quotes
- My Garage (`/dashboard/vehicles`) — client's registered vehicles
- Settings (`/dashboard/settings`) — redirects to `/dashboard/admin/settings`
- Note: `/dashboard/receipts` is linked in sidebar but page does NOT exist yet

## Database Schema — CRITICAL NOTES

### ⚠️ schema.sql LAGS BEHIND LIVE DB

The `schema.sql` file does NOT fully reflect the live Supabase database. Always verify column names against the actual database when writing queries.

### Reviews Table (VERIFIED)

```sql
reviews (
  id               UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  user_id          UUID REFERENCES profiles(id) ON DELETE SET NULL NOT NULL,
  quote_id         UUID REFERENCES quotes(id) ON DELETE SET NULL,
  customer_name    TEXT NOT NULL,
  customer_email   TEXT,           -- exists in live DB, NOT in schema.sql
  rating           INT NOT NULL CHECK (rating >= 1 AND rating <= 5),
  comment          TEXT NOT NULL,   -- named 'comment' NOT 'review_text'
  status           TEXT NOT NULL DEFAULT 'pending',
  moderation_notes TEXT,
  approved_at      TIMESTAMPTZ,
  deleted_at       TIMESTAMPTZ,
  created_at       TIMESTAMPTZ DEFAULT NOW(),
  updated_at       TIMESTAMPTZ DEFAULT NOW()
)
```

**Rules for review code:**
- Read: `review.comment` (NOT `review.review_text`)
- Read: `review.customer_email` (may be null)
- Write: `comment` field in insert
- Omit: `vehicle_serviced` entirely (column does NOT exist)
- Required: `user_id` must be included in inserts (NOT NULL constraint enforced)

### ⚠️ profiles table — schema.sql MISSING MANY COLUMNS

The `types/database.ts` defines ~20+ columns for `profiles` that do NOT exist in `schema.sql`:
`company_name`, `logo_url`, `address`, `vat_number`, `registration_number`, `bank_name`, `account_holder`, `account_number`, `branch_code`, `hourly_rate`, `callout_fee`, `diagnostic_fee`, `terms_conditions`, `default_deposit_percent`, `alternate_phone`, `physical_address`, `prefers_whatsapp`, `service_reminders_opt_in`, `client_status`, `internal_notes`

When modifying profile-related code, verify the column exists in the actual database first.

### ⚠️ vehicles table — schema.sql MISSING COLUMNS

`license_plate` and `mileage` exist in types but NOT in schema.sql.

### ⚠️ No `is_admin()` function exists

schema.sql does NOT contain an `is_admin()` function. Role checking is done via `user.user_metadata.role` in the middleware.

## Error Handling (CRITICAL)

```typescript
// ❌ NEVER do this:
setError(error.message);

// ✅ ALWAYS use sanitizers:
import { sanitizeAuthError, sanitizeFormError } from '@/lib/auth-utils';
setError(sanitizeAuthError(error));   // auth forms
setError(sanitizeFormError(error));   // database forms
```

### ReviewForm Error Mapping
```typescript
function getErrorMessage(code, message) {
  if (code === 'PGRST204') return 'A database column is missing.'
  if (code === '23505') return 'This review already exists.'
  if (code === '42501') return 'No permission to submit.'
  if (code === '23502') return 'You must be signed in to submit.' // user_id NOT NULL
  if (message?.includes('does not exist')) return 'Database schema mismatch.'
  return message || 'Something went wrong.'
}
```

## Accessibility Standards

1. **Semantic HTML** — use `<button>`, `<nav>`, `<main>`, `<section>` — never `<div onClick>`
2. **ARIA Labels** — `aria-label`, `aria-expanded`, `aria-describedby`
3. **Focus** — keyboard navigation, visible focus rings, logical tab order
4. **Contrast** — `text-white on bg-primary` is valid; `text-white on bg-grey-light` is invalid (low contrast)

---

## Performance

1. **Tree-shaking** — use named imports from lucide-react: `import { Wrench } from 'lucide-react'`
2. **Dynamic pages** — always `export const dynamic = 'force-dynamic'` on pages with DB queries
3. **External images** — use `<img>` tags until Supabase Storage is configured (no `next/image` remote patterns needed yet)

## Known Issues

### Fixed
1. Circular CSS Variables — fixed by using direct hex values in `@theme`
2. Heading Colors Override — fixed by removing element selectors from variables.css
3. DynamicIcon tree-shaking — fixed with named imports + static map
4. Hero dead buttons — fixed by wrapping `<Button>` in `<Link>` when href provided
5. Error leaks — fixed with sanitizeAuthError / sanitizeFormError
6. Nested main tag — fixed by replacing inner `<main>` with `<>` fragment in page.tsx
7. Schema-DB mismatch (reviews) — fixed types/schema to use `comment` not `review_text`
8. Reviews auth gating — ReviewForm now requires auth, sends user_id
